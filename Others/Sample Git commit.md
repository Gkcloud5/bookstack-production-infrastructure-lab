# How to name commits

A very common professional convention is:

<type>: <short description>


Example:

```text
feat: add Docker Compose configuration
fix: resolve container startup issue
docs: update setup instructions
refactor: simplify Dockerfile
test: add health check test
chore: update dependencies
```

### Common types

| Type | Use for | Example |
|---|---|---|
| `feat` | New functionality | `feat: add Docker Compose setup` |
| `fix` | Bug fix | `fix: resolve database connection issue` |
| `docs` | Documentation | `docs: update installation guide` |
| `refactor` | Code improvement without behavior change | `refactor: simplify application config` |
| `test` | Tests | `test: add API health check` |
| `chore` | Maintenance | `chore: update Docker image version` |
| `build` | Build/dependency changes | `build: add production dependencies` |
| `ci` | CI/CD changes | `ci: add GitHub Actions workflow` |
